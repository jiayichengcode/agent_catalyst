## 1. 一句话说明

我们在多任务 agentic RL 里问:**任务 C 加速无关任务 B 的学习,这个效应到底由什么承载?**
本试点用"同样的任务、同样的交互经验、只改变哪些 rollout 进入梯度"的干预,判定效应承载在
**任务级**(C 在不在)还是**轨迹级**(C 的哪类 rollout 进梯度),以及是不是特定的
**错误恢复(err_recovery)轨迹**在起作用。

## 2. 实验设置

### 2.1 任务三元组(全合成、可无限生成、判分程序化)

| 角色 | 任务 | 内容 | 关键设计 |
|---|---|---|---|
| **B(目标任务)** | `sql_query` | 多轮 text-to-SQL:3 张表、随机化表/列名(同义词池),模型必须先查 schema 再答题;5 回合预算 | 随机列名逼出 `no such column` 报错;基线失败模式=报错后**重复同一条错误查询直到回合耗尽**(校准时实测) |
| **C(加速候选)** | `pyfix` | 读报错修一行:给带单行 bug 的 Python 函数+可见测试,工具 `run`/`submit`,隐藏测试判分 | 60% 实例首跑必报错(练"读 traceback→定点修"),40% 实例可见测试全过但隐藏测试挂(练"读代码找 bug",产生无报错轨迹) |
| **填充** | `neutral_format` | 单轮 JSON 重排,无工具无报错 | 用于 noC 条件补齐混合,保持 batch 结构不变 |

**为什么这对 C→B 能构成"跨任务迁移"检验**:两个任务共享同一个行为模式——
"读错误观察 → 修正假设 → 换动作重试 → 及时提交",但领域(Python vs SQL)、工具、答案形式完全不同。
若 C 加速 B,"领域知识迁移"解释被构造性削弱,"行为迁移"解释被支持——这正是 plan §0 想判别的机制。

**难度校准结果**(Qwen3.5-4B 基线,2 轮迭代后):B 贪心 pass@1=0.646(n=48),C=0.583,
温度 1 下 C 成功率 0.458 且几乎所有成功都经过报错(err_recovery 供给充足但非全部)。

### 2.2 训练配置(所有条件严格共享)

- 模型 Qwen3.5-4B;自研 minimal GRPO(严格 on-policy 组基线策略梯度,adv=r−mean(group),无 KL、不除 std)
- 每步:sql 4 实例 + pyfix 4 实例 + neutral 2 实例,每实例 G=8 条 rollout,温度 1.0
- 每条 run 独占 2×H100(卡 A:vllm 采样引擎,卡 B:策略训练;每步后权重经 /dev/shm 同步回 vllm)
- 每 10 步在**held-out** 实例上做贪心 eval(B 48 题、C 24 题、neutral 12 题) → 学习曲线
- 每条 rollout 自动打 trace 特征行(success/err_event/err_recovery/verify_cnt/replan/len/ent/adv_mag)落盘

### 2.3 六个条件(前 4 条正在跑,后 2 条排队)

所有条件里 **B 和 neutral 的训练完全相同**,唯一差别是 C 的处理:

| 条件 | C 的采样/交互 | C 的哪些 rollout 进梯度 | 回答的问题 |
|---|---|---|---|
| **noC** | C 移出采样池,neutral 补齐 | — | 加速效应是否存在(与 F6 对比) |
| **F6** | 正常 | 全部 | 正对照(标准多任务 RL) |
| **F3** | 正常(超采样×3 后按 token 预算下采样) | **仅 err_recovery 轨迹**(报错且最终成功) | 效应是否由错误恢复轨迹承载 |
| **F5** | 正常(同 F3 超采样) | 与 F3 **同批次等量**(条数+token 双匹配)的随机轨迹 | 排除"只是多了些 C 梯度"的数量解释 |
| F0(排队) | 正常 | **全不进**(只交互不学习) | 区分"梯度通道"vs"rollout 分布通道"(plan 的隐藏彩蛋对照) |
| F1(排队) | 正常 | 仅成功轨迹 | success-only RFT 惯例是否丢弃迁移载体 |

**关键机制(A3, advantage-frozen)**:过滤发生在**梯度计算前、优势计算后**——GRPO 优势永远在完整
G=8 组上算(baseline 无偏),被滤掉的 rollout 只是 loss 全 token 置零。Agent 的交互经验在
F0/F3/F5/F6 间**完全同分布**,唯一自变量=进入梯度的轨迹集合。这是监督学习做不到的对照
(同数据、同经验、不同梯度),是本设计的方法学核心。

## 3. 预期结果与判读(写在开盲前)

主读数:**B(sql_query)的 eval 曲线**——time-to-τ(τ=0.75/0.8)、AUC、终点;
辅助读数:C 曲线、各条件进入梯度的 C token 数(已逐步记录,用于算力对齐检查)。

### 情形 A:trace 级承载(我们押注的主线,对应 plan 的 O-trace/O-span 路线)
```
B 曲线:F6 ≈ F3  >  F5 ≈ F0 ≈ noC
```
- F6>noC:加速对成立(G1 通过的试点版)
- F3≈F6:只保留 err_recovery 轨迹(≈C 梯度 token 的~1/3)就保住全部加速 → 载体是特定轨迹
- F3>F5:等量随机轨迹不行 → 不是数量效应,是**轨迹内容**
- **含义**:plan 的核心假设在小尺度成立,phase-2 加 seeds+F 条件补全,直接照 O-trace 骨架写论文,并推进 E7(span 级)

### 情形 B:任务级承载(O-task 备胎)
```
F6 ≈ F3 ≈ F5  >  noC(且 F0 也 ≈ F6)
```
- 过滤什么都不影响,只要 C 在混合里就行 → 效应是任务整体属性
- **含义**:反转主张"轨迹内容无关紧要"——对 success-only RFT 惯例是个有趣的否定,中档论文;若 F0≈F6 更劲爆(光交互不学习也加速→效应经由 B 自己的 rollout 分布变化)

### 情形 C:无加速
```
F6 ≈ noC
```
- 这对构造的 (C,B) 没有跨任务加速 → 换任务对重试(如 C=失败重规划 drill)或上 E1 的系统性搜索;试点设计上已用"共享行为、异领域"最大化了成功概率

### 情形 D(需要警惕的混淆模式)
- **B 曲线普跌、noC 跌最狠**(v1 被中止的运行里 noC 的 sql eval 从 0.65 掉到 0.52 有此苗头):
  加速可能表现为"C 防止 B 的策略退化"(格式漂移/熵塌缩)而非加速上升。判读时要看熵和格式错误率,
  必要时把叙事从"加速"改成"稳定+加速"——机制问题不变,仍是"什么承载了这个保护效应"
- F3 的 C token 数与 F6 差距过大 → 看 kept_tok 日志做算力对齐核查(±容忍带内才可比)
- 全条件都平但都涨:lr 或步数不够,延长或加 lr 重跑

### 统计口径(试点级)
单 seed,只做方向判断与效应量点估,**不做显著性宣称**;phase-2 对胜出对比加 3 seeds + bootstrap CI
+ Holm 校正(plan §6 统计条款),那才是论文证据。
